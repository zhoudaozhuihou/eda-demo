## 1. 产品概述

### 1.1 产品定位
数据 API 平台是一款企业级统一数据服务中间件，旨在连接底层数据源（数据库、数据仓库）与上层应用（前端应用、报表、第三方系统）。它提供可视化的 API 构建、发布、管理与监控能力，实现数据的快速服务化。

### 1.2 目标用户群体
*   **API 开发者/后端工程师**：通过低代码方式快速构建数据接口，减少重复 CRUD 开发工作。
*   **数据工程师**：注册与管理数据资产，维护数据血缘与元数据。
*   **数据分析师**：自主查询数据，通过 API 获取所需数据集，无需依赖开发排期。
*   **系统管理员/运维**：管理数据连接、用户权限、系统配置及监控 API 运行状态。

### 1.3 核心价值主张
1.  **研发提效**：提供"单表查询"、"多表关联"、"批量生成"等多种 API 构建模式，将 API 开发时间从小时级缩短至分钟级。
2.  **统一治理**：集中管理数据权限与敏感数据脱敏（Masking），确保数据安全合规。
3.  **资产沉淀**：建立统一的 API 与数据集目录，解决数据孤岛问题，提升数据复用率。
4.  **全生命周期管理**：覆盖 API 的创建、测试、发布、版本控制、审批、下线等全流程。

## 2. 模块划分与详细说明

### 2.1 仪表板 (Dashboard)
*   **模块概述**：平台运营数据的可视化概览页面，提供核心指标监控与快捷入口。
*   **核心功能**：
    *   **指标卡片**：展示 API 总数、数据源数量、数据集数量、今日调用量。
    *   **快捷导航**：快速跳转至数据集管理、API 构建、文档中心等核心功能。
    *   **热门 API 榜单**：基于调用量排名的 Top API 列表，辅助发现高价值资产。
    *   **性能监控**：展示系统整体健康度（延迟、错误率趋势）。
*   **前置条件**：用户登录系统。

### 2.2 数据集管理 (Dataset Management)
*   **模块概述**：数据资产的核心注册与管理中心，支持元数据维护、权限申请与血缘分析。
*   **核心功能**：
    *   **数据集检索**：支持按分类（Domain）、标签、名称进行模糊搜索与筛选。
    *   **详情展示**：
        *   **基本信息**：名称、别名、所属项目、更新时间、行数统计。
        *   **字段定义**：列名、类型、别名、描述、是否脱敏（Masked）。
    *   **变更历史 (Change History)**：
        *   记录元数据变更日志（操作人、时间、动作、详情）。
        *   提供宽幅对话框展示，支持时间筛选与分页查看。
    *   **血缘分析 (Lineage)**：可视化展示数据集的上游数据源与下游关联 API，辅助影响面分析。
    *   **权限申请 (Auto Package)**：
        *   集成 MaxCompute Package 授权流程。
        *   支持选择项目、有效期（30天/90天/永久）、具体数据表。
        *   提交后自动生成审批单。
*   **业务流程**：
    *   注册数据集 -> 配置字段/脱敏 -> 申请权限(Auto Package) -> 审批通过 -> 可用于构建 API。

### 2.3 API 构建器 (API Builder)
*   **模块概述**：可视化的 API 生成工具，支持从数据集直接发起构建。
*   **核心功能**：
    *   **构建模式**：
        *   **单表模式 (Single Table)**：基于单张表的快速 CRUD。
        *   **多表关联 (Join Mode)**：可视化的 Inner/Left/Right Join 配置。
        *   **注入点模式 (Injection Mode)**：支持动态 SQL 条件注入的高级模式。
        *   **批量模式 (Batch Mode)**：基于模板批量生成多个 API。
    *   **向导式流程 (Wizard)**：
        1.  **模式选择**：选择上述四种模式之一。
        2.  **基础配置**：设置 API 名称、路径、请求方法、鉴权方式 (API Key/OAuth2)。
        3.  **参数定义**：配置入参（类型、是否必填、默认值）与出参。
        4.  **SQL 预览**：实时生成 SQL，支持语法检查与性能评分。
        5.  **发布配置**：设置 QPS 限流与缓存策略。
*   **输入/输出**：
    *   输入：选定的数据集或数据源表。
    *   输出：可调用的 API 接口定义。

### 2.4 API 目录 (API Catalog)
*   **模块概述**：面向消费者的 API 门户，提供发现、测试与文档服务。
*   **核心功能**：
    *   **分类浏览**：按业务域展示 API 列表。
    *   **文档详情**：自动生成接口文档（Path, Method, Params, Response）。
    *   **在线调试**：内置 HTTP 客户端，支持参数输入与实时调用测试。
    *   **文档导入**：支持导入 OpenAPI/Swagger 规范文件。

### 2.5 审核中心 (Approval Center)
*   **模块概述**：统一的审批工作流管理中心。
*   **核心功能**：
    *   **审批类型**：
        *   **API 生命周期**：发布 (Publish)、更新 (Update)、下线 (Deprecate/Delete)。
        *   **权限申请**：Access Package 申请（MaxCompute 资源包）。
    *   **审批详情**：
        *   展示申请人、申请原因、时间。
        *   针对 Access Package，展示项目、有效期及申请表清单。
    *   **审批操作**：通过 (Approve) / 拒绝 (Reject)，支持填写审批意见。
*   **状态流转**：
    *   Pending (待审批) -> Approved (已通过) / Rejected (已拒绝)。

### 2.6 管理中心 (Management Center)
*   **模块概述**：基础设施接入与系统配置。
*   **核心功能**：
    *   **数据源管理**：
        *   支持 MySQL, PostgreSQL, MaxCompute 等多种数据源。
        *   MaxCompute 专用管理：Project 列表、Table 列表同步。
    *   **环境配置**：开发/测试/生产环境配置。
    *   **权限管理**：用户与角色配置。

## 3. 核心业务流程图

### 3.1 Auto Package 权限申请与 API 发布流程
```mermaid
graph TD
    A[数据工程师/开发者] --> B{数据集是否可用?}
    B -- 否(无权限) --> C[数据集详情页]
    C --> D[点击 Apply Permission]
    D --> E[填写申请单 (项目/有效期/表)]
    E --> F[提交 Access Package 申请]
    F --> G[审核中心: 管理员审批]
    G -- 拒绝 --> H[流程结束 (需修改后重提)]
    G -- 通过 --> I[自动执行 MaxCompute 授权]
    I --> B
    B -- 是(有权限) --> J[API 构建器]
    J --> K[配置 API (模式/参数/SQL)]
    K --> L[提交 API 发布申请]
    L --> M[审核中心: API 审批]
    M --> N[API 上线 (Published)]
```

## 4. 数据实体模型 (Updated)

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | string | UUID |

| :--- | :--- | :--- |

## 5. 交互与体验要求

### 5.1 响应式设计
*   **Change History 对话框**：
    *   在大屏下宽度应自适应至 90% 视口宽度 (Max 1152px)，确保表格内容完整显示不折行。
    *   移除水平滚动条，内容溢出时自动换行。
    *   支持内部垂直滚动，表头需固定 (Sticky)。
*   **移动端适配**：
    *   侧边栏在移动端应自动折叠为 Drawer 菜单。
    *   复杂表格在移动端应转换为卡片视图或支持横向滑动。

### 5.2 导航交互
*   **SPA 路由**：全站采用单页应用架构，使用 `eda:navigate` 自定义事件进行模块间跳转，避免页面整页刷新。
*   **状态保持**：从列表页进入详情页再返回时，应保持列表页的筛选条件与页码状态。

## 6. 异常处理规范

1.  **API 构建异常**：
    *   当 SQL 语法检查失败时，需在编辑器下方实时显示错误行号与原因。
    *   禁止提交包含高危关键字 (DROP, TRUNCATE, DELETE without WHERE) 的 SQL。
2.  **权限异常**：
    *   用户访问无权限的数据集时，应直接引导至 "Apply Permission" 申请流程，而非仅显示 403 错误。
3.  **服务降级**：
    *   当后端 API Gateway 不可用时，前端应展示友好的 "系统维护中" 页面，并提供重试按钮。
