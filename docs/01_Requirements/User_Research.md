## 1. 调研背景
为验证 Data API Platform 的产品价值并优化功能设计，我们对内部潜在用户进行了深度访谈与问卷调查。

## 2. 用户画像 (Personas)

### 2.1 典型用户 A：李明 (后端开发工程师)
*   **痛点**: 每天接到大量报表查询接口需求，逻辑简单但重复性高（CRUD），占用了核心业务开发时间。
*   **诉求**: 希望能自动生成简单的查询接口，只需编写 SQL 或配置即可。
*   **现有方案**: 手写 Controller/Service/Dao，平均一个接口耗时 2-4 小时（含测试）。

### 2.2 典型用户 B：王芳 (数据分析师)
*   **痛点**: 数仓数据在 MaxCompute 中，取数需要写 SQL 导出 Excel，无法直接给前端应用使用；申请后端开发排期长。
*   **诉求**: 能自助将数仓表发布为 API，供自己的数据看板直接调用。
*   **现有方案**: 依赖后端排期，通常需等待 3-5 天。

## 3. 调研结论

### 3.1 关键发现
1.  **开发效率低**：80% 的数据查询接口是简单的单表或双表关联，人工开发性价比极低。
2.  **沟通成本高**：前端、后端、数据开发三方在字段定义、数据类型上反复沟通，缺乏统一文档。
3.  **安全隐患**：部分临时接口未做脱敏处理，直接返回了明文手机号。

### 3.2 需求优先级排序
1.  **自动化构建 (P0)**: 必须支持通过 SQL 或界面配置直接生成 API。
2.  **在线调试 (P0)**: 提供类似 Postman 的在线测试能力。
3.  **权限审批 (P1)**: 数据敏感度高，上线前必须经过审批。
4.  **自动脱敏 (P1)**: 无需写代码即可实现手机号、身份证脱敏。
