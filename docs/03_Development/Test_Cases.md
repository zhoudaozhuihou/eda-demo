## 1. 测试策略
*   **单元测试**: 覆盖核心 Utils 和 Redux Reducers。
*   **集成测试**: 覆盖 API 构建流程、数据源连接。
*   **UI 测试**: 覆盖关键交互（表单验证、弹窗）。

## 2. 功能测试用例 (Functional)

| ID | 模块 | 用例名称 | 前置条件 | 操作步骤 | 预期结果 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| TC-001 | 数据源 | 连接 MySQL 成功 | MySQL 服务可用 | 1. 输入 Host/Port/User/Pass<br>2. 点击"测试连接" | 提示"连接测试通过" |
| TC-002 | 数据源 | 连接失败处理 | 密码错误 | 1. 输入错误密码<br>2. 点击"测试连接" | 提示"认证失败"或具体错误信息 |
| TC-003 | API构建 | 单表查询生成 | 已有数据集 | 1. 选择数据集<br>2. 勾选字段<br>3. 点击下一步 | 自动生成 `SELECT col1, col2 FROM table` |
| TC-004 | API构建 | 参数校验 | 无 | 1. API 路径输入中文 | 提示"路径仅允许字母、数字、/" |
| TC-005 | 审批 | 批准 API 上线 | 待审核任务存在 | 1. 管理员点击"批准" | API 状态变更为 Published，申请人收到通知 |

## 3. 性能测试用例 (Performance)
*   **PT-001**: API 网关并发测试。目标：单机 1000 QPS，延迟 P99 < 50ms。
*   **PT-002**: 大数据查询超时处理。目标：MaxCompute 查询超过 10s 自动转为异步或提示。

## 4. 安全测试用例 (Security)
*   **SEC-001**: SQL 注入测试。输入参数 `id = 1 OR 1=1`，预期被转义或拦截。
*   **SEC-002**: 越权访问。用户 A 尝试编辑用户 B 的 API，预期 403 Forbidden。
*   **SEC-003**: 敏感数据泄露。API 返回结果中，手机号字段应显示为 `138****1234`。
