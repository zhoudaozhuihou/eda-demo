BACKGROUND
项目背景

项目背景与产品定位

核心问题

  • 效率瓶颈 — 从业务需求到 API 上线平均需 3-5 天，沟通成本高
  • 安全风险 — 手动编写 SQL 存在注入、数据泄露等安全隐患
  • 合规压力 — 金融级数据治理要求（PBOC/CBIRC）难以自动落地
  • 知识孤岛 — 数据库 Schema 分散、数据血缘不透明、治理困难

产品定位

  • AI Native — 基于 LangGraph 的 18 节点 Agentic 工作流引擎
  • 安全优先 — 内置 SQL 验证、风险分级、六层合约门禁、合规引擎
  • 全链路闭环 — 从自然语言到生产级 API 的一站式智能管道
  • 企业级 — 多数据源、RBAC/ABAC、审计追踪、数据血缘治理

市场机遇

  • 数据民主化 — 业务人员可直接通过自然语言获取数据
  • API 经济 — 低代码平台与 API 市场对快速 API 生成需求激增
  • 合规科技 — 金融监管趋严，自动化合规检查成为刚需
  • AI Agent — 大模型能力成熟使 NL→SQL 达到实用水平

目标用户

  • 数据分析师 — 快速获取数据洞察，无需等待开发排期
  • 后端开发者 — 通过自然语言生成 API 代码原型
  • 数据治理团队 — 自动化血缘追踪与合规检查
  • 低代码平台 — 集成智能 API 构建能力

REVIEW & OPTIMIZE
审核优化

人工审核与 SQL 优化

人工审核节点

  • SQL 预览 — 展示生成的 SQL 及对应的自然语言描述
  • 风险提示 — 标注风险等级、涉及敏感字段、预估数据量
  • 人工确认 — 审批/驳回/修改 SQL，记录审批人信息
  • 结果确认 — 执行前展示模拟结果，人工确认后放行

审计追踪

  • 完整审计日志 — 每次查询/API 生成均记录
  • 异步写入 SQLite + stdout，不阻塞主流程
  • 审批操作全留痕，满足金融审计要求
  • 工作流状态可追溯、可回放

SQL 优化策略

  • 行数限制 — 自动追加 LIMIT，防止大数据量查询
  • 超时保护 — 查询超时配置，避免长时间占用连接
  • 结果模拟 — 采样查询预览，确认结果符合预期
  • 索引推荐 — LLM 辅助优化查询计划

审核子图流程

SQL 预览 → 风险标注 → 人工确认 → SQL 优化 → 结果模拟 → 二次确认 → 合约生成

CONTRACT GATE
合约门禁

六层合约工程门禁

Schema

校验 API 合约与数据库 Schema 的一致性 — 字段名、类型、是否可空、默认值是否匹配数据库定义

Shape

校验请求/响应结构的完整性 — 参数是否齐全、嵌套结构是否合理、数组类型是否正确

Semantics

校验语义逻辑 — 字段含义是否准确、参数约束是否合理、是否与查询意图一致

Evidence

校验数据证据 — 是否有实际数据支持该合约、样例数据是否符合预期、边界情况处理

Policy

校验策略合规 — 是否满足数据访问策略、敏感字段是否标记脱敏、权限是否匹配

Quality

校验整体质量 — 合约完整性评分、可读性评估、最佳实践检查、安全红线扫描
